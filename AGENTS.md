# skills — repo guidance

Witek's personal, harness-neutral agent skills. This is the canonical
instructions file for this repo (`CLAUDE.md` is just `@AGENTS.md`).

Consumed two ways:

- Claude Code discovers skills at `~/.claude/skills`.
- Codex discovers skills at `~/.agents/skills`.

Both are symlinks to `skills/` in this repo, created by
`dotfiles/symlink/symlink.sh`.

## Layout

Skills live in group directories at the repo root — `engineering/`, `ios/`
— one directory per skill, e.g. `engineering/commit/`, `ios/ios-project/`.
Add more groups simply by adding a new top-level directory containing
skills; there's no registration step beyond that.

- `SKILL.md` — required: frontmatter (`name`, `description`) plus the body.
- `references/`, `scripts/`, `templates/` — optional, loaded/used on demand.

`skills/` is a flat farm of relative symlinks, one per skill, generated by
`./link.sh` and committed to git. Both harnesses actually read from here —
Claude Code only discovers `<dir>/SKILL.md` one level deep, so the farm
gives it (and Codex) a single flat directory while the real files live
grouped. Tool-installed skills (currently `sentry-cli`) are the exception:
they live directly in `skills/<name>` as a real directory, not moved into a
group, and are gitignored by name since an installer owns and rewrites
them in place.

## Authoring rules

- `name` in frontmatter must equal the directory name.
- `description` states concretely when to use the skill — that's what
  triggers it, so be specific rather than generic.
- Keep bodies harness-neutral: no Claude- or Codex-specific tool names in
  prose. Put long or harness-specific material in `references/` instead.
- Domain-specific skills carry a domain prefix (`ios-…`); general
  engineering skills don't. Both harnesses see one flat namespace in
  `skills/`, where a collision between two same-named skills from
  different groups would be silent, so the prefix is what keeps names
  unique — not the group directory.
- Run `./link.sh` after adding, renaming, or removing a skill.

Edits to an existing `SKILL.md` are live immediately in both harnesses
(the farm symlinks straight through to the group directories). Adding,
renaming, or removing a skill needs a `./link.sh` run to update the farm.
