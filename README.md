# skills

Agent skills split out of [dotfiles](https://github.com/witekbobrowski/dotfiles) because they're a different kind of thing: dotfiles is private plumbing for my machines, skills are reusable playbooks worth sharing and worth keeping clean on their own. Same brain, different repo.

## What's here

Skills are grouped into top-level directories — `engineering/`, `ios/` —
one directory per skill. Domain-specific skills carry a domain prefix
(`ios-`) and general ones don't; the prefix is what keeps names unique once
both harnesses see them in one flat namespace (more on that below).

### General engineering

| Skill | Description |
|---|---|
| `engineering/commit` | Stage and commit the current changes following the repo's commit message conventions. |
| `engineering/create-pr` | Open a pull request whose title and description follow the repo's conventions. |
| `engineering/review-pr-comments` | Read a PR's review comments, judge each one, implement only the good suggestions, and reply with the decision. |
| `engineering/adr` | Write an Architecture Decision Record into the repo's `Docs/adr/` (or `docs/adr/`) following its numbering and template. |
| `engineering/claude-reviewer` | Cross-vendor code review: run the local Claude Code CLI headlessly to review a finished change set so a second model family catches what a Codex-side review misses. |

### iOS

| Skill | Description |
|---|---|
| `ios/ios-project` | Interactive wizard that scaffolds a new iOS app repository from Witek's personal blueprint. |
| `ios/ios-app-group` | Sets up an App Group in an iOS app the right way — entitlement wiring, a shared-defaults access point, store-file placement in the group container, and the migration path when adopting late. |
| `ios/ios-swiftdata` | Wizard that designs and scaffolds a SwiftData truth-store package following Witek's proven architecture. |

## How it's wired

Two symlinks, both created by `dotfiles/symlink/symlink.sh`:

- `~/.claude/skills` -> `skills/` (this repo), so Claude Code picks them up.
- `~/.agents/skills` -> `skills/` (this repo), so Codex picks them up.

`skills/` itself is a flat farm of relative symlinks into `engineering/` and
`ios/`, generated by `./link.sh` and committed to git — Claude Code only
discovers skills one level deep, so the farm is what gives both harnesses a
single flat directory while the real files live grouped. Edit a `SKILL.md`
in its group directory and both harnesses see it immediately; adding,
renaming, or removing a skill needs a `./link.sh` run to update the farm.

Tool-installed skills (right now `sentry-cli`, dropped in by the Sentry CLI
installer) live straight in `skills/` and are gitignored — not mine to
version.

## Adding a skill

1. Create `<group>/<name>/SKILL.md` (e.g. `engineering/<name>/SKILL.md` or `ios/<name>/SKILL.md`) with `name` (matching the directory) and a `description` that says exactly when to reach for it.
2. Run `./link.sh` to add it to the `skills/` farm.
3. Commit.

Keep the body harness-neutral — no Claude- or Codex-specific tool names in prose. Push long or reference-y material into `<group>/<name>/references/`, and any scaffolding into `scripts/` or `templates/`.
